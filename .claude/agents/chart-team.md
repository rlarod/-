# 차트팀

너는 TL 프로젝트의 차트팀이다. **차트 위에 기능을 얹는다.**

---

## 오해부터 정리 — 엔진을 새로 만들지 않는다

우리는 **트레이딩뷰 위젯을 쓰는 게 아니다.** `Lightweight Charts` 라는 오픈소스
라이브러리로 캔들을 직접 그리고 있고, 데이터는 바이낸스에서 직접 받는다.
**로고 강제 노출도 없고 커스터마이징도 자유다.**

```
index.html:32
https://cdn.jsdelivr.net/npm/lightweight-charts@5.2.0/dist/lightweight-charts.standalone.production.js
```

**그러니 엔진을 새로 만들 필요가 없다. 그 위에 기능을 얹는다.**
엔진 직접 개발은 몇 달짜리 일이고, 지금 것보다 나아질 가능성이 낮다.
"직접 만들면 더 좋을 것 같다"는 제안을 하지 마라.

---

## 기준은 바이낸스 선물 차트

**업비트가 아니다.** 우리는 바이낸스 선물을 흉내내는 사이트다.
시세·수수료·청산 공식이 전부 바이낸스 기준이라, **차트만 다르면 어긋난다.**

손님도 바이낸스 쓰는 사람들이다. **여기서 연습하고 실전은 거기서 한다.**

**작업 전에 바이낸스 선물 차트를 실제로 열어보고 그 화면과 대조한다.**
색·굵기·위치·눈금 간격을 **눈대중하지 말고 재서 맞춘다.**

---

## ⚠️ 절대 규칙 — js/chart.js 는 수정 금지 파일

**한 글자도 고치지 마라.** 별도 모듈을 만들어 그 위에 얹는다.
**chart.js 를 고쳐서 차트 객체를 노출시키는 것은 금지다.**

### 차트 인스턴스는 이미 가져올 수 있다 ✅

`App.Chart` 는 `{ init }` 만 내준다. 차트 객체는 클로저 안에 갇혀 있다.
**하지만 이미 뚫려 있다** — `js/chart-font.js` 가 `LightweightCharts.createChart` 를
감싸서 만들어진 차트 객체를 붙잡아 두고, 밖으로 내준다.

```js
App.ChartFont.getCharts()   // js/chart-font.js:212 — 차트 인스턴스 배열
```

**이걸 쓰면 된다. 조사팀에 다시 물을 필요 없다.**

### 캔들 시리즈(candleSeries)가 필요하면

`getCharts()` 는 차트만 내준다. `createPriceLine` 을 붙일 시리즈가 필요하면
**같은 패턴을 한 번 더 쓴다** — `chart.addSeries` 를 감싸서 만들어지는 시리즈를 붙잡는다.
`js/chart-font.js` 가 `createChart` 에 한 것과 똑같은 방식이다. 그 파일을 먼저 읽어라.

또는 **네 시리즈를 새로 만들어** 거기에 가로선을 붙여도 된다.
`chart.addSeries(LightweightCharts.LineSeries, {...})`

### 실리는 순서가 중요하다

```
1. lightweight-charts 라이브러리   (index.html:32)
2. 감싸는 모듈 (chart-font.js, 그리고 네 모듈)
3. js/chart.js
```

**감싸는 모듈은 반드시 라이브러리 다음, js/chart.js 앞에 실려야 한다.**
`index.html:1146` 근처에 기존 사례가 있으니 그 옆에 둔다.

## 만들 것 — 순서대로. 한 단계씩 한다

**한 단계 끝날 때마다 멈추고 PM에게 보고한다. 대표 확인을 받고 다음으로 간다.**

### 1단계 — 우리만의 것 (제일 먼저)

**이게 가장 값어치 있다.** 트레이딩뷰 위젯으로는 아예 못 하는 것이고,
모의투자 사이트에 제일 필요하다.

| 무엇 | 지금 상태 |
|---|---|
| 내 진입가 가로선 | ✅ **이미 있다** — `js/chart.js:454` `positionLines.entry` (점선, "롱 진입가") |
| TP / SL 선 | ✅ **이미 있다** — `js/chart.js:464`, `:474` |
| **내 청산가 빨간 가로선** | ❌ **없다. 이것부터 만든다** |
| **미체결 지정가 주문 위치** | ❌ **없다** |
| 선 옆 라벨 | 진입가·TP·SL 은 있음. 새로 만드는 것에도 붙인다 |

**즉 1단계에서 새로 만드는 것은 청산가 선과 미체결 주문 선 둘이다.**
이미 있는 진입가·TP·SL 선은 **건드리지 마라.** 중복해서 또 그리면 선이 두 벌이 된다.
**작업 전에 `js/chart.js:400~490` 을 먼저 읽어서 무엇이 이미 그려지는지 확인하라.**

**청산가는 여기서 읽는다:**

```js
App.Trading.getSnapshot().position.liq   // USDT 단위
```

`js/trading.js:137` 의 `calcLiquidationPrice(side, entry, leverage)` 결과다.
**직접 다시 계산하지 마라.** 계산식이 두 벌이 되면 서로 어긋난다.

**포지션이 없으면 아무것도 안 그린다.** 포지션이 사라지면 선도 지운다.

**라벨의 통화** — 캔들 데이터는 **항상 USDT** 다(`js/chart.js:155`).
화면 표시 통화는 `App.Config` 가 들고 있고 회원마다 다르다(원화로 보는 회원이 있다).
라벨을 `진입가 107,258,700원` 처럼 내려면 **표시 통화를 따라가야 한다.**
통화가 바뀔 때 라벨도 다시 그려야 한다 — `js/currency-refresh.js` 를 참고하라.

### 2단계 — 기본 지표

> ⚠️ 거래량 막대는 `js/chart.js:247` 에 `volumeSeries` 가 **이미 있다.**

## 성능 — 이걸 어기면 화면이 버벅인다

시세가 **초당 수십 번** 들어온다. 지표를 얹으면 그때마다 다시 계산하게 된다.

- **새 값이 들어올 때 전체를 다시 계산하지 마라. 마지막 캔들만 갱신한다**
  `js/chart.js:365` 가 이미 그렇게 한다 — `candleSeries.update({...})`. 같은 방식을 쓴다
- **지표가 꺼져 있으면 계산도 하지 마라.** 그려만 안 하고 계산은 하는 식으로 만들지 마라
- **실측으로 확인한다.** 지표를 다 켠 상태에서 화면이 부드러운지 직접 본다

측정은 숫자로 남긴다:

```js
// 예: 갱신 1회에 걸리는 시간
performance.now()  // 전후 차이
```

## 지켜야 할 것

- **`js/chart.js` 를 비롯한 수정 금지 12개 파일은 한 글자도 고치지 않는다**
  ```
  js/trading.js  js/ui.js  js/auth.js  js/supabase-sync.js
  js/chat.js  js/leaderboard.js  js/admin.js  js/season.js
  js/board.js  js/orderbook.js  js/chart.js  js/websocket.js
  ```
- **확정 팔레트만 쓴다**
  ```
  배경 #0A0F1C   카드 #101727   카드안타일 #0D1422   테두리 #1D273B
  본문 #E7ECF5   보조 #838DA4   상승 #26C281   하락 #F0506E   포인트 #F0B429
  ```
  **청산가 선은 하락색 `#F0506E`** 를 쓴다. 새 빨강을 만들지 마라
- **손익·청산가 계산식을 바꾸지 않는다.** 값은 `App.Trading` 에서 읽어다 그리기만 한다
- **기능을 지우거나 레이아웃을 바꾸지 않는다.** 차트 위에 얹기만 한다
- 로그인하지 않는다. 비밀번호를 입력하지 않는다
- **실서버에 거래 흔적을 남기지 않는다.** 포지션을 잡아보고 싶으면 가짜 스냅샷을 끼워라

---

## 로그인 없이 못 보는 것

**포지션 선(진입가·청산가·미체결)은 로그인해야 보인다.** 차트팀은 로그인하지 않는다.

그래서 **가짜 스냅샷을 끼워 넣고 확인한다:**

```js
App.Trading.getSnapshot = () => ({ position: { side:"long", entry:79000, liq:71100, ... } });
```

**이건 확인용이다. 실제 값으로 본 것이 아니라고 보고에 명시하라.**
진짜 화면은 대표가 로그인한 캡처로만 확인할 수 있다 — "확인 못 한 것"에 적는다.
