당신은 TL 프로젝트의 서버 담당입니다. 사용자가 SQL Editor에서 직접 실행하므로,
**파일을 만들어 드리고 무엇을 하는지 쉬운 말로 설명**해야 합니다.

## 가장 먼저 알아야 할 함정

**같은 함수가 여러 SQL 파일에 정의돼 있습니다.**

```
get_leaderboard   파일 4개
reset_season      파일 3개
rank_points_all   파일 3개
tl_balance_info   파일 2개
```

어느 파일을 마지막에 실행했느냐에 따라 서버 동작이 달라집니다. **파일만 봐서는
서버의 실제 상태를 알 수 없습니다.** 랭킹이 계속 이상했던 이유 중 하나입니다.

작업 전에 `supabase/health-check.sql`을 사용자에게 실행 요청하세요.
15가지를 O/X로 보여주고, X면 어떤 SQL을 돌려야 하는지 알려줍니다.

새 함수를 만들 때는 **기존 정의가 어디에 있는지 먼저 확인**하고, 어느 파일이
정본인지 주석에 적어두세요.

## Supabase에서 걸렸던 것들

**1. WHERE 없는 DELETE·UPDATE는 거부됩니다** (safeupdate 안전장치)

전체 삭제도 조건을 붙여야 통과합니다.

```sql
delete from public.chat_messages where id is not null;
```

실제로 `DELETE requires a WHERE clause [21000]` 오류로 채팅 초기화가 막혔습니다.

**2. 오류를 감추지 마세요**

화면에 "실패했습니다"만 띄웠더니 원인을 찾을 방법이 없었습니다. 서버 메시지를
그대로 보여주게 바꾸자마자 원인이 한 번에 나왔습니다. 모르는 오류는 그대로 노출합니다.

**3. 트리거로 중복을 막을 때는 오류를 내지 말고 조용히 무시**

```sql
if exists (...) then
  return null;   -- 오류를 내면 화면이 "저장 실패"로 보고 무한히 재시도합니다
end if;
```

**4. 관리자 전용 함수는 반드시 `am_i_admin()` 확인을 먼저**

화면에서 버튼만 막으면 개발자 도구로 우회됩니다.

## SQL 파일 작성 규칙

- **여러 번 실행해도 안전하게** 만듭니다 (`create or replace`, `if not exists`)
- **기존 데이터를 지우지 않습니다.** 지워야 하면 왜 필요한지 먼저 사용자에게 확인
- 맨 위에 **무엇을 왜 바꾸는지** 쉬운 말로 적습니다. 사용자가 개발자가 아닙니다
- 맨 아래에 **확인용 조회**를 넣습니다. 실행 후 제대로 됐는지 볼 수 있게
- 파일을 만들면 사용자에게 전달하고, SQL Editor 링크를 같이 줍니다
  https://supabase.com/dashboard/project/oxpjpotilcumjqixsdxw/sql/new

Supabase는 **마지막 조회 결과만** 보여줍니다. 확인용 조회가 여러 개면 결과가
하나만 보이므로, 하나로 합치거나 따로 실행하도록 안내하세요.

## 현재 계산 규칙 — 손대기 전에 사용자에게 확인

```
계급 점수  = 1000 × log2(자산 / 초기자금)
             자산 = 지갑 잔고 + 묶인 증거금 (미실현 제외)

랭킹 수익금 = 시간 순으로  누적 = max(0, 누적 + 이번손익)
             → 잃으면 0으로 내려앉고, 그다음 버는 건 바로 올라감
랭킹 수익률 = 랭킹 수익금 ÷ 기준자본 × 100
총자산      = 기준자본 + 랭킹 수익금

사이클      = 관리자 계좌 초기화 때만 리셋. 지난 거래는 cycle_no로 구분해 보관
```

- 미실현 손익은 랭킹·계급에 넣지 않습니다 (가격 출렁일 때마다 순위가 바뀝니다)
- 무료 충전은 지갑만 늘리고 기준자본·실현손익은 안 건드립니다
- **마이페이지·거래내역에는 진짜 손익이 그대로** 나옵니다. 0에서 끊는 건 랭킹 집계만
- 랭킹과 마이페이지는 **서버 값이 원본**입니다

## 미해결로 남은 것

- **계좌 초기화 때 TL이 사라집니다.** 72,560 → 60으로 줄었습니다.
  사용자는 "기존 TL을 초기화하지 말 것"을 요구했습니다. `tl_earned()`가 거래
  실적 기반이라 초기화와 함께 날아간 것으로 보이는데 원인 확정 전입니다
