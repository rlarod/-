# 팀 7개

TL 프로젝트의 실무 조직입니다. 각 `.md` 파일이 그 팀의 지침입니다.

```
                    대표 (김경환)
                          │
                    사업본부장 ── 감사팀
                          │
   ┌────────┬────────┼────────┬────────┬────────┐
   ▼        ▼        ▼        ▼        ▼        ▼
 점검팀   조사팀   수리팀   디자인팀   기록팀   차트팀
```

| 팀 | 파일 | 하는 일 | 고칠 수 있나 | 하루 제한 |
|---|---|---|---|---|
| **점검팀** | `qa-team.md` | 증상 찾기 + 수정 후 실측 | ❌ 없음 | 없음 |
| **조사팀** | `bug-hunter.md` | 원인만 찾기 | ❌ **도구 자체가 없음** | 없음 |
| **수리팀** | `repair-team.md` | 화면·서버 고치기 | ✅ | 없음 (한 건씩) |
| **디자인팀** | `design-team.md` | 보기·쓰기 개선 | ✅ | 없음 |
| **기록팀** | `test-writer.md` | 재발 방지 테스트 | ✅ `tests/` 만 | 없음 |
| **차트팀** | `chart-team.md` | 차트 위에 기능 얹기 | ✅ `chart.js` 제외 | 없음 |
| **감사팀** | `audit-team.md` | **누가 놀고 있는지** 본부장에게 보고 | ⚠️ 아주 단순한 것만 | 없음 |

> **감사팀은 본부장 직속이고 실무 6팀의 상사가 아닙니다.**
> 다른 팀에게 직접 지시하거나 업무를 배정하지 않습니다.
> **감시 → 확인 → 판단 → 본부장에게 즉시 보고** 까지가 역할이고,
> **업무 배정은 오직 사업본부장이** 합니다.

## 일이 흘러가는 순서

```
증상 발견 (점검팀)
   │
   ▼
게이트 1 — 본부장이 직접 재현.  안 되면 배정 안 함
   │
   ▼
원인이 확실한가?
   ├─ 아니오 →  조사팀  →  "확신도: 확실" 나올 때까지
   └─ 예
   ▼
수리팀 / 디자인팀 이 고침
   │
   ▼
점검팀이 여섯 폭으로 실측  ←  숫자가 여기서 나온다
   │
   ▼
게이트 2 — 본부장이 직접 검증
   해시 12/12 · npm test · 직접 열어보기 · 되돌리는 법
   │
   ▼
통과 = 승인.  커밋·푸시 → 라이브 확인
   │
   ▼
기록팀이 재발 방지 테스트로 못 박음
```

## 핵심 규칙 세 가지

**1. 조사 없이 고치지 않는다.**
원인이 확실하지 않으면 수리팀에 배정하지 않고 조사팀에 먼저 보냅니다.
랭킹 -180억 건에서 원인을 확정하지 않고 세 번 고쳤다가 **세 번 다 엉뚱한 곳**이었습니다.

**2. 조사팀에는 고칠 도구가 없습니다.**
`bug-hunter.md` 의 `tools:` 에 `Edit`·`Write` 가 없는 것은 실수가 아니라 설계입니다.
**이 목록을 바꾸지 마세요.**

**3. 어느 팀도 자기 작업을 스스로 통과시키지 않습니다.**
승인은 본부장이 게이트 2에서 합니다.

## 공통으로 지키는 것

- **수정 금지 파일 12개** — 한 글자도 고치지 않습니다. 필요하면 별도 모듈로 우회합니다
- **화면 확인은 여섯 폭 전부** — 360 / 375 / 390 / 768 / 1440 / 1920
- **로그인하지 않습니다** — 비밀번호를 입력하지 않습니다
- **SQL 실행은 대표만** — 팀은 파일과 실행 순서만 알려줍니다
- **회원 데이터를 지우거나 초기화하지 않습니다**
- **보고에 "확인 못 한 것"을 반드시 따로 둡니다**

상세 규칙은 `CLAUDE.md` 와 `docs/인계문서.md` 를 따릅니다. 충돌하면 `docs/인계문서.md` 가 우선합니다.
