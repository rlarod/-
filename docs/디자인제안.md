## 2. 우리가 더 나은 부분 (바이낸스를 그대로 따를 이유가 없는 곳)

무조건 맞추는 게 목적이 아니므로 먼저 적습니다.

1. **호가창 글자 20px vs 바이낸스 12px.** 바이낸스 모바일 호가는 12px/400 에 행 피치 20px 입니다.
   우리는 20px/600 에 행 피치 33px. 대신 우리는 5단계씩만 보여줍니다.
   **한글·노안 가독성에서 우리가 확실히 낫습니다.** 줄이지 말 것을 권합니다.
2. **누적(총수량) 열이 있다.** 바이낸스 모바일 호가에는 Size/Price 두 열뿐입니다.
   우리는 가격·수량·총수량 3열이라 시장 두께를 더 잘 보여줍니다.
3. **비로그인 상태에서도 계산이 다 보인다.** 매수가격·매도가격·매수금액·매도금액·
   강제청산·유지증거금률·수수료·필요증거금이 주문 패널에 그대로 있습니다.
   바이낸스 모바일은 비로그인이면 Log In 버튼만 보입니다. **모의투자 사이트에는 우리 쪽이 맞습니다.**
4. **매수/매도 압력 바(50%/50%)** 가 주문창 안에 바로 있습니다. 바이낸스 모바일에는 이 자리에 없습니다.
5. **숫자에 `tabular-nums` 를 넓게 걸어둔 것.** 바이낸스는 대표가격·호가 모두
   `font-variant-numeric: normal` 입니다(BinanceNova 자체가 고정폭 숫자라 눈에 안 띌 뿐).
   우리는 웹폰트가 못 뜰 때도 자릿수가 흔들리지 않습니다. **그대로 두는 게 낫습니다.**
6. **24H 지표에 "24H" 접두와 `$` 단위를 붙여 뜻이 분명하다.** 바이낸스는 라벨이 10px 라
   실제로 읽기 힘듭니다.

지금 360px 에서 **6개 지표 중 4개가 화면 밖**입니다. 회원이 옆으로 밀지 않으면
고가·저가·거래량·펀딩비를 볼 수 없습니다. 바이낸스는 같은 360px 에서 전부 보여줍니다.

## 6. 제안 — 큰 변경

> "큰 변경" = **구조**를 바꿉니다. 대표가 고를 문제입니다.
> **어느 것도 기능을 지우지 않습니다.** 화면에서 뺄 때는 CSS 로 숨기고 마크업은 남깁니다.

이미 재료가 있습니다 — `js/orderbook-tabs.js` 에 `showTab()`(좁은 화면 탭 전환)과
`showStacked()`(넓은 화면 상하 배치)가 있고, `index.html` 에 `data-tab="orderbook"` /
`data-tab="trades"` 버튼이 있습니다. **여기에 차트 탭을 하나 더 붙이는 모양**입니다.

**왜** 모바일에서 호가를 보려면 지금 **1307px 을 스크롤**해야 합니다.
바이낸스는 탭 한 번입니다.

- 같은 테스트가 `index.html` 의 `data-tab="orderbook"` / `data-tab="trades"` **버튼 보존**을
  요구합니다. 탭 이름을 바꾸더라도 이 속성은 남겨야 합니다.
- `#orderbook-tabs-content.ob-stacked` CSS 도 남아 있어야 합니다.

  `chart.js` 는 수정 금지 파일이라 우회가 필요합니다. 탭 전환 시 `resize` 를 다시 쏴야 합니다.

화면 맨 아래에 **고정 바(높이 약 64~80px)** 를 두고 `매수 / Long` · `매도 / Short` 를 올립니다.

**깨질 위험**
- 고정 바가 **면책 문구·채팅·푸터를 가립니다.** 문서 맨 아래에 바 높이만큼 여백이 필요합니다.

  바이낸스는 로그인/가입입니다. 우리는 **모의투자라 비로그인도 계산을 보여주는 게 강점**이므로
  그대로 매수/매도를 두고 누르면 로그인 안내를 띄우는 쪽이 맞을 수 있습니다.
- ⚠ **로그인 후 바이낸스 하단 바에 정확히 무엇이 들어가는지는 확인 못 했습니다** (로그인 안 함).

### L3. 주문 패널을 접기 (인라인 1148px → 요약 + 펼치기)

**무엇을 → 어디로**
주문 패널을 **① 항상 보이는 부분**(교차/레버리지 · 지정가/시장가 · 가격 · 수량 · % · 매수/매도)과
**② 접히는 부분**(계산정보 · 계좌 3줄 · 강제청산/수수료 · 무료충전 안내 · 종목 목록)로 나눕니다.
②는 `▾ 자세히` 로 펼칩니다. **CSS 로 접을 뿐 마크업은 그대로 둡니다.**

**왜** 1148px 은 한 화면(844px)보다 깁니다. 주문 하나 넣으려고 두 화면을 넘겨야 합니다.

**효과** 1148px → 약 560px (**−590px**)

**깨질 위험**
- `tests/order-panel.test.js` 가 주문창 안 여러 요소의 **최소 크기와 위계**를 검사합니다
  (기본 ≥16px, 라벨 ≥14px·≥17px, 입력값 > 계좌값 > 라벨, 버튼 > 라벨).
  **접기만 하고 크기는 건드리지 않으면** 걸리지 않습니다.
- `display:none` 으로 접으면 **그 안의 값이 갱신되는지 확인해야 합니다.**
  안 갱신되면 펼쳤을 때 옛날 숫자가 보입니다 → **조용한 고장**입니다.
  `visibility`/`height:0` 으로 접는 쪽이 안전할 수 있습니다.
- 강제청산가·수수료를 접으면 **회원이 위험 정보를 못 보고 주문**할 수 있습니다.
  → 이 둘은 **접지 말고 항상 보이는 부분에 남기는 것**을 권합니다.

### L4. 시세 블록을 스크롤해도 위에 붙여두기 (검토만)

| 펀딩비 라벨 `white-space:nowrap` | ❌ 잘림 — "펀딩비 (다음 정산까지)" 가 한 칸에 안 들어감 |
| 펀딩비 라벨 `white-space:normal` + `word-break:keep-all` | ✅ 두 줄로 접히면서 단어가 안 쪼개짐 |

**권고안 — "숫자·영문은 바이낸스 쪽으로, 한글은 조정"**

```
숫자(가격·수량·비율)  →  바이낸스 쪽으로 좁혀도 됨. 단 우리 테스트 하한선 안에서
한글 라벨            →  바이낸스보다 1~2px 크게 (10px → 11.5px)
한글 행간            →  1.45~1.5 (바이낸스 영문은 1.6 이지만 절대값이 작음)
한글 줄바꿈          →  word-break: keep-all (단어 중간에서 안 쪼개지게)
```
