## 2. 정보 밀도 — 한 화면에 값이 몇 개 들어가나

첫 화면(스크롤 0) 안에서 실제로 보이는 텍스트 노드 수와 그중 숫자꼴 값 수를 셌습니다.
(`display:none`·`visibility:hidden`·화면 밖 제외)

| 폭 | 바이낸스 텍스트 / 숫자 | 우리 텍스트 / 숫자 | 숫자 배수 |
|---|---|---|---|
| 1440 | **235 / 111** | 66 / 9 | **12.3배** |
| 1440 (우리를 y700로 스크롤해 거래 영역을 띄운 상태) | 235 / 111 | 90 / 44 | 2.5배 |
| 390 | **107 / 22** | 44 / 5 | **4.4배** |
| 360 | **108 / 22** | 44 / 5 | **4.4배** |

> 우리 1440 첫 화면의 숫자 9개는 **전부 시세 바** 값입니다. 호가·주문·포지션 숫자는 0개입니다.
> 스크롤해서 거래 영역을 띄워도 44개로, 바이낸스의 **40%** 입니다.

밀도 차이의 원인은 글자 크기 하나가 아닙니다. 셋입니다.

1. **거래와 무관한 블록이 먼저 온다** — 로고 139 + 공지 201 + 배너 134 = 474px
2. **호가 단수가 5+5** — 바이낸스는 데스크톱 7+7, 모바일 20+20
3. **행 높이** — 우리 호가 행 35px vs 바이낸스 20px

## 11. ⚠ 수정 금지 파일이 걸리는 지점

각 항목마다 ① 무엇을 하려는데 어느 파일이 걸리는가 ② 우회 가능한가 ③ 우회하면 얼마나 지저분해지는가.

### A. 포지션·주문내역 표의 열 이름·순서·탭 구성을 바꾼다

- **걸리는 파일: `js/ui.js`** (757줄, 236~312줄 `buildTabbedPanel()`)
- `js/ui.js:309` 에서 **`historyPanel.innerHTML = ""` 로 `.history-panel` 을 통째로 비우고 다시 조립합니다.**
  탭 5개(`포지션(0)/미체결(0)/주문내역(0)/거래내역/자산`)를 `innerHTML` 문자열로 만들고,
  기존 `.position-section`·`#pending-order-card` 를 `appendChild` 로 옮깁니다.
- **주문내역 표의 `<th>` 7개(`시각·방향·유형·가격·레버리지·증거금·상태`)와

- **우회 가능한가:** 가능합니다. **이미 하고 있습니다** — `js/position-table-extra.js`(314줄)가
  ui.js 이후에 돌면서 칸 4개를 더 넣고 탭 이름을 `미체결→미체결주문`, `거래내역→마감손익` 으로
  바꾸고 `#cloud-history-panel` 을 숨깁니다.
- **한 줄 평:** 칸 4개 추가 + 탭 2개 이름 변경에 **314줄**이 들었습니다. 열 순서까지 바꾸려면
  ui.js 가 만든 `<thead>` 를 다시 파싱해 재배열해야 해서 이 파일이 500줄대로 갑니다. **지저분합니다.**

### B. 호가 단수를 5+5 → 바이낸스처럼 늘린다

- **걸리는 파일: `js/orderbook.js`** — `const DEPTH_LEVELS = 5;` (40줄)
- 이 상수는 **CSS가 아니라 WebSocket 주소**에 쓰입니다:
  `"wss://fstream.binance.com/public/ws/" + symbol + "@depth" + DEPTH_LEVELS + "@" + STREAM_SPEED`
  (70줄). 즉 **5호가만 받아오고 있습니다.** CSS로는 절대 못 늘립니다.
- 행 DOM도 orderbook.js 가 `createElement`+`innerHTML` 로 만들고(149~151줄)
  `rAF` 마다 `textContent`/`style` 만 갱신합니다(169~172줄).
- **우회 가능한가:** 기술적으로는 가능합니다 — 별도 모듈이 `@depth20` 스트림을 **두 번째로** 열고
  자기 행을 그리면 됩니다. 하지만 ① 소켓이 3개가 되고 ② 기존 `.ob-row` 10개와 새 행이 겹쳐
  둘 중 하나를 숨겨야 하며 ③ `orderbook:update` 이벤트를 듣는 `market-war.js`·
  `orderbook-mark-price.js`·`orderbook-click-order.js` 가 어느 쪽 데이터를 봐야 하는지 갈립니다.
- **⚠ 그리고 `tests/top-panel.test.js:1573` 이 `const DEPTH_LEVELS = 5;` 문자열을 강제합니다.**
- **한 줄 평:** 우회가 아니라 **사실상 두 번째 호가창을 새로 만드는 일**입니다. 매우 지저분합니다.
  → **원본을 열지 않으면 호가 단수는 못 늘립니다. 대표 판단이 필요합니다.**

### D. 차트를 탭 뒤로 숨긴다 (차트/호가/체결 한 자리)

- **걸리는 파일: `js/chart.js`**
- ✅ **좋은 소식:** `chart.js:186` 이 `createChart(..., { autoSize: true })` 입니다.
  lightweight-charts 가 내부 ResizeObserver 로 컨테이너를 따라갑니다. `chart.js` 에는
  `window.addEventListener("resize")` 도 수동 `resize()` 호출도 **없습니다.**
  1회차에서 "탭 전환 시 resize를 다시 쏴야 한다"고 적었는데 **정정합니다 — 자동입니다.**
- ⚠ 단 `display:none` 이면 컨테이너가 0×0 이라 ResizeObserver 가 0으로 한 번 잡습니다.
  다시 보일 때 복구되는지는 **실제로 눌러 확인해야 합니다.** `visibility:hidden` + 화면 밖
  이동 쪽이 안전합니다.
- ⚠ 그리고 `style.css:430` 의 `height:max(1150px, calc(100vh - 380px))` 주석이
  **"행 높이를 내용 기준으로 두면 차트가 무한히 커지는 되먹임이 실제로 있었다"** 고 적고 있습니다.
  `tests/top-panel.test.js:1125` 가 `min-height:max(` 사용을 금지합니다.
- **한 줄 평:** **CSS만으로 됩니다.** 다만 "차트가 안 보이는 동안 시세가 계속 갱신되는지"를

페이지 전환은 `App.PageNav.showPage()` 로 했습니다. **이 방법 때문에 한 번 잘못 볼 뻔했습니다.**

- `showPage()` 로만 넘기면 그 로딩이 **아예 안 돕니다.** 그래서 처음에
