## 🔴 TL-004 · [P1] 차트를 1초·5초·15초로 두면 손익·강제청산이 통째로 멈춤

| 간격 | 로컬 | 라이브 | 판정 |
|---|---|---|---|

| **5초** | **0회** | **0회** | 죽음 |
| 15초 | **0회** | — | 죽음 |
| 1분 | 30회 | 28회 | 정상 |
| 5분 | 17회 | — | 정상 |

같은 시간 호가창(`orderbook:update`)은 24회로 **정상**입니다. 부분 고장이 아니라
가격 신호만 딱 죽습니다.

### 무엇이 멈추나 (코드로 확인)

`js/trading.js:671` 이 `price:update` 하나에 전부 걸려 있습니다.

```

                 └→ checkTriggers (488행)
                      ├→ 강제청산 판정   (493~494행)
                      ├→ 익절(TP) 판정   (496~499행)
                      └→ 손절(SL) 판정   (500~503행)

```

**따라서 1초·5초·15초에서는 이것들이 전부 안 돕니다:**

- ❌ **강제청산이 안 됨** — 청산가를 지나쳐도 포지션이 살아 있음
- ❌ **손절(SL)이 안 걸림** — 회원이 걸어둔 안전장치가 조용히 무력화
- ❌ **익절(TP)이 안 됨**
- ❌ **지정가 주문이 안 체결됨**
- ❌ **미실현 손익이 멈춘 숫자로 보임**

### 왜 P1 인가

- **돈에 직결**: 손절을 걸어놨는데 안 걸립니다. 회원은 걸린 줄 압니다
- **조용함**: 오류가 없어 회원이 고장인 줄 모릅니다
- **라이브에서 재현됨**: 지금 쓰는 회원이 겪을 수 있습니다
- 완화 요소: 기본값이 `1분` 이라, **1초·5초·15초를 직접 누른 회원만** 해당됩니다

### 원인 (수리팀 확정)

`js/config.js:131-138` 의 `buildCombinedStreamUrl()` 이 `/market` 경로로 접속하는데,
체결 스트림 `@trade` 는 바이낸스의 `/public` 경로에만 있습니다. 바이낸스는 없는
스트림 이름을 받아도 **오류를 내지 않고 연결을 유지**해서, 같은 연결의 kline·ticker 는
정상인데 `@trade` 만 한 건도 안 옵니다.

1분 이상 간격은 kline 스트림으로 가격을 받지만, **1초·5초·15초는 바이낸스에 없는
간격이라 체결로 캔들을 직접 만들게 되어 있습니다**(`js/websocket.js:148-163`).
그 체결이 안 오니 가격도 안 옵니다.

수리팀 실측:

## 🔴 TL-005 · [P1] 매수/매도 압력 바가 항상 정확히 50:50 — 데이터가 아니라 "없음"의 대체값

**등록** 2026-08-21 15:10 · **상태** ✅ 해결 (2026-08-24 — js/order-pressure-bar.js. 실제 60초 거래량 집계)

### 현상

주문창의 **매수/매도 비율 바가 언제나 `매수 50% / 매도 50%`** 를 표시합니다.
전쟁터의 매수·매도 강도도 마찬가지로 전부 0 입니다.

**균형 잡힌 시장처럼 보이지만, 사실은 "데이터가 하나도 없음"입니다.**

### 원인 (코드로 확정, 추측 아님)

`js/market-war.js:1254`

```js
function getBuySellRatio() {
  const total = buyIntensity + sellIntensity;
  const buyPct = total > 0 ? (buyIntensity / total) * 100 : 50;   // ← total 0 이면 50
  return { buyPct: Math.round(buyPct), sellPct: Math.round(100 - buyPct) };
}
```

`buyIntensity` / `sellIntensity` 는 **오직 체결 신호에서만** 늘어납니다
(`js/market-war.js:498-499`, 갱신 경로는 1216행의 `App.Bus.on("trade:tick", ...)` 하나뿐).

**TL-004 와 같은 이유로 `trade:tick` 이 0회**이므로 두 값은 영원히 0 이고,
`total > 0` 이 거짓이 되어 **항상 50 이 반환**됩니다.

`js/order-pressure-bar.js` 가 이 값을 그대로 주문창 압력 바에 씁니다.

### 왜 P1 인가

- **"모름"을 "반반"으로 보여줍니다.** 빈 화면이면 회원이 이상하다고 느끼지만,
  50:50 은 **그럴듯한 정상값처럼 보여서 회원이 그대로 믿습니다**
- 매수/매도 압력은 **진입 방향을 정하는 근거**입니다. 잘못된 근거로 돈을 겁니다
- 오류도 경고도 없습니다 — 조용한 고장의 전형

### 확인된 근거

- 코드 경로 3곳 대조 (갱신처 / 대체값 / 사용처)
- 2026-08-21 11:05 화면 실측에서 `매수 50%  매도 50%` 확인
- TL-004 실측: `trade:tick` 10초간 **0회**

### 고치는 방법

**TL-004 를 고치면 같이 해결됩니다.** 체결 신호가 살아나면 두 값이 실제로 갱신됩니다.

**추가로 권장** — 데이터가 없을 때 50 을 반환하지 말고 "데이터 없음"을 표시해야 합니다.
지금 구조는 스트림이 또 끊겨도 아무도 모릅니다. `js/market-war.js` 는 수정 금지가
아니지만, 표시 쪽(`js/order-pressure-bar.js`)에서 처리하는 편이 안전합니다.

## TL-010 · [P1] 랭킹이 전원 0원 — 원인 미확정

**등록** 2026-08-24 · **상태** ⏸ 대표 SQL 결과 대기 · **담당** 미배정

`get_leaderboard` RPC 를 직접 불러도 3명 전부 이렇게 옵니다.

```
CHRO   총자산 100,000 / 수익금 0
Mang9  총자산 100,000 / 수익금 0
김갱    총자산 100,000 / 수익금 0
```

같은 화면 채팅에는 오늘(한국시간 8/24) 김갱님 거래 **7건**이 있습니다. 합계 **-220,579,147원**.

랭킹 계산은 `profit_amount = trading_accounts.realized_pnl` 입니다
(`supabase/schema-ranking-fix.sql:46`). 즉 **서버의 realized_pnl 이 0** 입니다.

**둘 중 무엇인지 못 가렸습니다.**

| | |
|---|---|
| (가) | 계좌가 초기화됨 — 거래기록은 있는데 손익만 0 |
| (나) | 손익이 안 쌓임 — 거래해도 realized_pnl 이 안 올라감 |

**본부장이 서버를 못 봅니다.** `supabase/조사-랭킹0원-2026-08-24.sql`(읽기 전용)을
대표에게 전달했고 결과를 기다립니다.

**손익·랭킹 계산식 변경은 대표 확인 항목**이라 추측으로 손대지 않습니다.

곁가지 — `profiles` 는 4명인데 랭킹에는 3명만 나옵니다(김갱TV 없음). 같은 조회로 확인됩니다.
