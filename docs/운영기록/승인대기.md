## 🔴 1. 대표 계정 잔고·실현손익을 어떻게 할지

### 무슨 일이 있었나

대표 캡처(2026-08-27 16:16 체결)에서 읽은 값 —

```
실현손익      -599,999,990원   ≈ -400,000 USDT
개시증거금     285,714,285원    ≈ 190,476 USDT
포지션        비트코인 241.652054 개 · 100배
```

### 감사팀이 확정한 것

**계산식은 정상입니다. 금액의 크기만 이상합니다.**

```
개시증거금 190,476.19 × 1.05 = 199,999.9995 ≈ 200,000.00
  → 진입 순간 지갑 잔고가 정확히 200,000 USDT 였습니다
  (js/trading.js:106-109 getMaxAffordableMargin 과 같은 식)

강제청산 1회의 실현손익 = -(margin + entryFee) = 그때 지갑에 있던 돈 전액
  지갑 100,000 → 정확히 -100,000
  지갑 200,000 → 정확히 -200,000
  → -400,000 = 100,000 전소 4회, 또는 200,000 전소 2회
```

**딱 떨어지는 200,000 은 "번 돈" 이 아니라 "받은 돈" 의 모양입니다.**
거래로 번 돈이면 187,342.11 같은 지저분한 숫자가 나옵니다.

### 선택지

| | 무엇 | 누가 하나 |
|---|---|---|
| **A** | 그냥 둔다 — 베타 테스트 흔적. 정식 오픈 때 한 번에 정리 | 아무것도 안 함 |
| **B** | 지갑 초기화 (100,000 으로 맞춤) | 대표가 포지션을 닫고 버튼을 누름 |
| **C** | 실현손익·거래기록까지 정리 | 본부장이 SQL 파일을 만들고 대표가 실행 |

**본부장 의견 — A 를 권합니다.** 베타이고 회원이 소수이며 정식 오픈 때 어차피 한 번 정리합니다.
**다만 랭킹에 대표님 값이 지금 보이고 있다면 B 나 C 가 낫습니다.**

⚠️ **랭킹에는 지금 안 보입니다** — `supabase/schema-leaderboard-floor.sql` 의 바닥 규칙 때문입니다.
**마이페이지에만 -400% 로 뜹니다.**

⚠️ **본부장 정정 (조사팀 지적)** — 처음에 "순손실이면 항상 0원" 이라고 적었는데 **틀렸습니다.**

```
바닥 규칙   랭킹수익금 = 전체합계 − min(0, 누적 최저점)

[-100, +30]  순손실인데 랭킹수익금은 +30    ← 0 이 아닙니다
```

**정확히는 "마지막 거래가 여태 최저점일 때만 0" 입니다.**
대표 계정이 지금 그 상태라 0으로 나오는 것이고, **손실 뒤에 조금이라도 벌면 그만큼 올라옵니다.**

**이 구분이 중요한 이유** — "순손실이면 항상 0" 으로 알고 있으면
**진짜 고장(바닥 뒤에 벌었는데 0으로 나오는 것)을 정상으로 넘기게 됩니다.**

**"A" 한 글자면 됩니다.**


### 왜 이렇게 됐나

이용권을 만들 때는 **기본 50배 + 이용권 쓰면 100배** 구조였습니다.
`js/leverage-gate.js:31` 주석에 그렇게 적혀 있습니다 —

> 지금은 모든 사용자에게 100배를 열어둡니다(이용권 없이도 100배 가능).
> 나중에 이용자가 많아지면 이 값을 50으로 내리기만 하면 즉시 전환됩니다.

**오늘 "일단 100배로 냅두자" 결정으로 이용권이 무의미해졌습니다.**
누구 잘못이 아니라 결정의 결과입니다.

### 선택지

| | 무엇 | 무엇이 바뀌나 |
|---|---|---|
| **A** | 이 상품을 판매 중지 | 회원이 헛돈 쓰는 것만 막습니다. 가장 간단합니다 |
| **B** | 기본 상한을 50배로 내린다 | 이용권이 다시 의미를 갖습니다. **회원 전원의 레버리지가 반으로 줄어듭니다** |
| **C** | 이용권 효과를 125배로 올린다 | 엔진 상한이 125라 실제로 열립니다. **오늘 "100배" 결정과 봉인 테스트에 걸립니다** |
