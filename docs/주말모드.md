# 주말 모드 — 무인 운영 헌장

금요일 밤부터 월요일 아침까지, 대표가 없는 동안 본부장이 혼자 도는 규칙입니다.
**회차마다 이 문서를 먼저 읽습니다.**

---

## ⭐ 0. 회차를 시작할 때 — 반드시 이 순서

새 회차는 **이전 회차를 전혀 기억하지 못합니다.**
그대로 두면 주말 내내 과제 1만 반복하게 됩니다.

```
1. docs/운영기록/진행상태.md 를 읽는다        ← 가장 먼저. 예외 없음
2. "다음에 할 것" 에 적힌 곳부터 이어서 시작한다
3. 일하는 중간중간 진행상태.md 를 갱신한다     ← 끊겨도 이어받을 수 있게
4. 회차를 마칠 때 진행상태.md 를 최종 갱신한다
```

**진행상태.md 를 안 읽고 시작하면 그 회차는 헛돈 것입니다.**

중간 갱신은 **과제 하나를 끝낼 때마다, 또는 발견을 3건 쌓을 때마다** 합니다.
한도 소진이나 오류로 회차가 갑자기 끊길 수 있습니다. 마지막에 몰아서 쓰면 다 날아갑니다.

## 1. 주말에는 찾고 준비만 합니다

대표가 없으므로 평소보다 **더** 엄격합니다.

### ❌ 절대 하지 않는 것

- **기존 코드를 고치지 않습니다.** 한 글자도.
- **커밋·푸시·배포하지 않습니다.**
- **수정 금지 파일 12개는 물론이고, 사이트 동작에 영향 가는 것은 아무것도 건드리지 않습니다.**
  `index.html`, `style.css`, `js/*.js`, `package.json` 전부 포함입니다.
- 회원 데이터·거래기록을 건드리지 않습니다. 실서버에 붙어 있습니다.
- SQL 을 실행하지 않습니다.
- 계정 비밀번호를 입력하지 않습니다. 로그인하지 않습니다.
- 진짜 돈이 나가는 일(유료 가입·무료 체험 포함)은 즉시 멈추고 기록만 합니다.

### ✅ 허용되는 것

- **문서 작성** — `docs/` 안의 모든 파일. 조사·기록·제안은 얼마든지.
- **읽기·측정·캡처** — agent-browser 로 열어보고 재는 것.
- **`tests/` 에 테스트 추가** ← 유일한 코드 예외

### 테스트 추가 규칙 (유일한 예외)

기존 코드를 안 건드리고 재발 방지 가치가 크므로 허용합니다. 단:

```
1. tests/ 안에만 새 파일을 만든다. 기존 테스트 파일을 고치지 않는다
2. package.json 의 test 목록에 등록한다 (이건 허용되는 최소 변경)
3. npm test 전체를 돌려 전부 통과하는지 확인한다
4. md5sum -c /tmp/baseline.md5 로 수정 금지 12개가 12/12 인지 확인한다
5. 위 3·4 결과를 진행상태.md 에 적는다
6. 하나라도 실패하면 방금 추가한 테스트를 지우고 기록만 남긴다
```

테스트 파일은 끝에서 `process.exit(0)` 을 부릅니다 (jsdom 이 안 끝납니다).

## 2. 주말 과제 (순서대로, 이어받기)

### 과제 1 — 바이낸스 전체 대조

`docs/점검팀.md` 의 점검 항목을 **하나씩 끝까지.** 대충 훑지 않습니다.
**실제로 바이낸스 선물(BTCUSDT)을 열어 나란히 비교**합니다.

시세 · 24H 고가/저가/변동률/거래량 · 마크가격 · 펀딩비 · 수수료율 ·
호가창 · 최근거래 · 청산가 계산 · 레버리지별 필요증거금

> **"의도된 차이"인지 "진짜 문제"인지 판단하지 않습니다. 둘 다 기록합니다.**
> 판단은 대표가 합니다. 값이 다르면 얼마나 다른지 숫자로 적습니다.

### 과제 2 — 거래 시나리오 전수

롱·숏 × 레버리지 여러 값(1·5·10·25·50·100) × 지정가·시장가 조합.
**진입부터 청산까지 실제로 눌러보고 계산을 직접 검산**합니다.
강제청산까지 재현되는지도 시도합니다.

검산 항목: 필요증거금 · 청산가 · 수수료(진입/청산) · 실현손익 · 잔고 변화

> 비로그인 상태에서 가능한 범위까지만 합니다. 로그인이 필요하면 "확인 못 한 것"에 적습니다.

### 과제 3 — 예외 상황 전수

수량 0 · 음수 · 문자 · 초대형 숫자 · 소수점 과다 ·
보유 자산 초과 주문 · 버튼 연타 · 주문 도중 새로고침 ·
뒤로가기 · 포지션 없이 청산 · 창 두 개 동시 조작

각각 무엇을 눌렀고 무엇이 나왔는지 그대로 적습니다.

### ⭐ 과제 8 — 조용한 고장 전수 점검 (신설, 우선순위 높음)

최근 체결 목록이 **패널은 멀쩡한데 영구히 비어 있었습니다.** 오류도 안 났습니다.
다른 곳에도 같은 게 있을 수 있습니다.

**화면에서 "비어 있는 것"을 전부 찾아, 진짜 비어 있는 건지 고장나서 비어 있는 건지
하나씩 가립니다.**

| 확인할 곳 | 무엇을 의심하나 |
|---|---|
| 인기글 "아직 인기글이 없습니다" | 진짜 없나, 안 불러오나 |
| 자유게시판·분석게시판 | "준비중"이 맞나, 고장인가 |
| 랭킹 목록 | 회원 전원이 다 나오나 (서버 회원 수와 대조) |
| 마이페이지 거래내역 | 실제 거래와 개수가 맞나 |
| TL 마켓·핫딜 상품 목록 | 상품이 다 나오나 |
| 전쟁터 매수/매도 비율 | **실제 데이터인가, 고정값인가** |
| 실시간 채팅 | 메시지가 실제로 흐르나 |

**각각 셋 중 하나로 반드시 결론냅니다:**

```
✅ 정상        진짜 비어 있음 — 데이터가 없는 게 맞음
❌ 조용한 고장  와야 할 게 안 옴
❓ 판단 불가    이유를 명시
```

**"아마 데이터가 없나 보다"로 넘어가지 않습니다.**

**가리는 방법:**

1. **신호 횟수 비교** — 정상 동작하는 것과 나란히 센다
   ```js
   const c={}; ['trade:tick','orderbook:update','chat:message'].forEach(n=>{c[n]=0;App.Bus.on(n,()=>c[n]++)});
   // 10초 뒤 c 를 본다. 한쪽만 0 이면 그쪽이 고장
   ```
2. **네트워크 요청이 실제로 오는지** 본다 (요청 자체가 없으면 안 부르는 것)
3. **서버 데이터와 대조** — 서버엔 있는데 화면에만 없으면 고장
   (SQL 은 실행하지 않습니다. 대표에게 어느 파일을 돌리면 되는지 알려주기만)

**고정값 판별**: 시간을 두고 두 번 재서 값이 똑같으면 고정값을 의심합니다.
전쟁터 매수/매도 비율이 특히 그렇습니다.

로그인이 필요한 곳(마이페이지 거래내역 등)은 **"판단 불가 — 로그인 필요"** 로 적습니다.

### 과제 4 — 코드 지도 만들기

`js/` 파일 81개가 각각 무슨 일을 하는지 정리해 **`docs/코드지도.md`** 로 만듭니다.
새 세션이 매번 처음부터 파악하지 않게 하는 것이 목적입니다.

한 파일당: 무슨 일을 하는가 / 누구를 건드리는가 / 수정 금지 파일과의 관계 /
우회 패턴을 쓴다면 어떤 것

**이 과제는 나눠서 해도 됩니다.** 진행상태.md 에 "81개 중 N개까지" 로 적습니다.

### 과제 5 — 백로그 조사

`docs/인계-보충.md` 의 "본부장 백로그" 미해결 항목들.
**원인을 조사하고 고치는 방법을 준비만** 합니다. 고치지 않습니다.

우선순위 두 가지:

1. **TL 이 계좌 초기화 때 사라지는 문제** — 72,560 → 60 으로 줄었습니다.
   `tl_earned()` 가 거래 실적 기반이라 초기화와 함께 날아간 것으로 보이나 원인 미확정.
2. **채팅창 위아래 흔들림** — `?jitter=1` 을 붙이면 진단 도구가 켜집니다
   (`js/jitter-probe.js`). **실제로 측정해서 숫자를 남깁니다.**
   어느 요소가 몇 번, 얼마나 높이가 변했는지.

### 과제 6 — 테스트 보강

오늘까지 나온 버그 유형을 **다시 못 잡을 테스트가 무엇인지** 보고 `tests/` 에 추가합니다.

알려진 취약 지점:
- 화면 폭별 가려짐 (컨테이너 안에서 잘리는 유형은 문서 폭 검사로 안 잡힘)
- 미디어쿼리마다 값이 달라지는 CSS 를 하나의 값으로 가정하는 검사
- 메모리로만 들고 있는 카운터 (새로고침하면 0 이 되는 유형 — 세 번 나왔음)
- 같은 CSS 규칙이 두 벌 (뒤엣것이 앞을 덮어 수정이 안 먹힘 — 두 번 나왔음)

**위 "테스트 추가 규칙" 6단계를 반드시 지킵니다.**

```

390   아이폰 표준

```

**360 부터 맞추고 위로 올라갑니다.** "390 에서 됐다"로 모바일을 통과시키지 않습니다.

**"화면 안에 있다"와 "읽을 수 있다"는 다릅니다.** 겹쳐 그리는 요소에 가리는지도 잽니다.

```js
const 겹침 = 대상.getBoundingClientRect().right - (컨테이너오른쪽끝 - 덮개폭);
// 0 이하여야 안 가려진 것
```

브라우저는 **agent-browser** 를 씁니다.

```bash
npm run dev                       # 안 떠 있으면. http://localhost:3000
agent-browser set viewport 360 800
agent-browser open http://localhost:3000
agent-browser wait 4000
agent-browser screenshot /tmp/weekend/r3-360.png
```

## 6. 월요일 아침 종합 보고

마지막 회차(월 08:00)는 **점검 대신 보고서만** 씁니다.

**`docs/운영기록/주말보고-YYYY-MM-DD.md`** (그 날짜)

주말 동안 40~50건이 쌓일 수 있습니다. **대표가 전부 읽지 못한다는 것을 전제로** 씁니다.
맨 위 다섯 개만 읽어도 판단이 서게 만듭니다.

```markdown
# 주말 보고 YYYY-MM-DD

## 1. 지금 당장 봐야 할 것 상위 5개
(각각: 무엇 / 왜 지금인지 / 실측값 / 재현 순서 / 캡처)

## 2. 대표 승인 필요
(항목 / 왜 승인이 필요한지 / 승인하면 무슨 일이 일어나는지)

## 3. 승인만 하면 바로 고칠 수 있는 것
(원인 확정 + 고치는 방법 준비 완료된 것. 되돌리는 방법도 함께)

## 4. 확인 못 한 것
(무엇을 / 왜 — 로그인 필요, 서버 권한 필요 등)

## 5. 나머지 전체 목록
(등급순. 한 줄씩)

---
## 요약 숫자
- 총 회차: N
- 총 발견: N건 (P1 N / P2 N / P3 N)
- 추가한 테스트: N개
- npm test 최종: N개 파일 / N개 통과 / 실패 N
- 수정 금지 파일 해시: 12/12 (또는 불일치 파일명)
- 코드 지도: 81개 중 N개
```

## 7. 회차를 마칠 때 — 체크리스트

```
[ ] 진행상태.md 를 최종 갱신했다 (완료·중단 지점·다음 할 것·누적 발견)
[ ] 코드를 고치지 않았다 (tests/ 추가 제외)
[ ] 커밋·푸시하지 않았다
[ ] 수정 금지 12개 해시 12/12 를 확인했고 기록했다
[ ] 테스트를 추가했다면 npm test 전체 통과를 확인했고 기록했다
[ ] "확인 못 한 것"을 적었다
```

`git status` 로 코드 파일이 바뀌지 않았는지 확인하고 그 결과를 진행상태.md 에 남깁니다.

## ⚠️ 로컬 서버가 몇 시간 돌면 죽는다 (EMFILE)

`npm run dev`(serve)가 브라우저 요청을 오래 받으면 열린 파일이 너무 많아져 죽는다.
2026-08-21 하루에 **두 번** 죽었다. 사이트 버그가 아니라 로컬 서버만의 문제다.

**브라우저 작업 전에 항상 확인하고, 죽었으면 다시 띄워라.**

```bash
timeout 10 curl -s -o /dev/null -w "%{http_code}" http://localhost:3000 || npm run dev &
```

측정이 갑자기 이상해지거나 요소를 못 찾으면 **서버부터 의심해라.**
실제로 "5분 버튼이 없다"는 결과가 나왔는데 서버가 죽어서 페이지가 안 뜬 것이었다.
