### 1-2. 기능·데이터 삭제 금지

화면에서 뺄 때는 **CSS로 숨기고 마크업은 보존**합니다. 나중에 되살릴 수 있어야
합니다. 실제로 이렇게 감춰둔 것들이 있습니다.

- 밝은 모드 — `js/theme.js`의 `DARK_ONLY = true`와 `#header-theme-btn{display:none}`
  두 줄만 되돌리면 살아납니다. 색 정의도 `style.css`에 그대로 있습니다
- 회원가입 — `.up-login-toggle{display:none;}` 한 줄. `js/auth.js`의 가입 코드는 그대로
- 마켓 상품 5종 — 지우지 않고 `status='paused'`

### 1-3. 가짜 데이터·숫자 금지

미구현은 "준비중" 배지로 표시합니다. 지어낸 숫자를 화면에 띄우지 않습니다.

- 고쳤으면 **실제 브라우저(Playwright)로 검증**하고 숫자를 보고합니다

- **막히면 추측하지 말고 중단하고 보고합니다.** 이 프로젝트에서 추측으로

## 3. 지금까지 고친 것 (중요한 것만)

### 반복해서 나온 버그 유형 — 앞으로도 이걸 의심하세요

**"페이지를 열 때마다 0이 되는 카운터"** 가 세 번 나왔습니다.

| 파일 | 변수 | 증상 |
|---|---|---|
| `js/trade-events-chat.js` | `lastSeenClosedCount` | 같은 청산 알림이 새로고침마다 다시 나감 |
| `js/supabase-sync.js` (수정금지) | `lastSyncedTradesCount` | 거래내역이 새로고침마다 통째로 다시 저장 → 7,261건 중복 |
| `js/cycle-pnl.js` 초기 버전 | 캐시한 Set | 창 두 개면 서로 못 봄 |

**메모리로만 들고 있는 카운터를 보면 의심하세요.** 저장소에 남기거나,
시각·id 같은 고유값으로 판단하도록 바꿔야 합니다.

**"같은 CSS 규칙이 두 벌"** 도 두 번 나왔습니다. `style.css`에 덧붙이다 보니
뒤엣것이 앞을 덮어써서 수정이 아예 안 먹혔습니다. 고쳐도 화면이 안 바뀌면
`grep -c` 로 중복부터 확인하세요.

### 손익·랭킹 계산 (가장 오래 걸린 부분)

현재 규칙입니다. 여기 손대기 전에 반드시 사용자에게 확인하세요.

```
계급 점수  = 1000 × log2(자산 / 초기자금)
             자산 = 지갑 잔고 + 포지션에 묶인 증거금 (미실현 제외)
             → 포지션 잡아도 계급 불변, 자산 줄면 강등, 원금 이하는 이병

랭킹 수익금 = 거래를 시간 순으로 훑으며  누적 = max(0, 누적 + 이번손익)
             → 잃으면 0으로 내려앉고, 그다음 버는 건 바로 올라감
             → 마이너스를 들고 가면 -18,158,792 을 다 메우기 전까지
               아무리 벌어도 0% 라 복구 불가능했습니다
랭킹 수익률 = 랭킹 수익금 ÷ 기준자본 × 100
총자산      = 기준자본 + 랭킹 수익금
```

- 미실현 손익은 랭킹·계급에 **넣지 않습니다**. 넣으면 가격이 출렁일 때마다
  순위가 오르내립니다
- 무료 충전(하루 2회 100,000)은 지갑만 늘리고 기준자본·실현손익은 안 건드립니다
- **마이페이지·거래내역에는 진짜 손익이 그대로** 나옵니다. 0에서 끊는 건 랭킹 집계만
- 랭킹과 마이페이지는 **서버 값이 원본**입니다(`js/cycle-pnl.js`). 예전에 마이페이지가
  브라우저 저장소를 보고 랭킹이 서버를 봐서, 랭킹 -180억인데 화면은 0원이었습니다

### 매매 사이클

랭킹은 "영구 누적"이 아니라 "현재 사이클" 기준입니다. **관리자 계좌 초기화** 때만
0%부터 다시 시작합니다. 지난 사이클 거래는 지우지 않고 `cycle_no`로 구분해 보관합니다.
일반 회원에게는 초기화 기능을 주지 않습니다.

### 수수료

`js/trading.js`가 청산할 때 `pnl = 총손익 - 청산수수료`로 기록하고
`fee = 진입수수료 + 청산수수료`(왕복)를 넣습니다. 진입 수수료는 **진입할 때 이미
지갑에서 빠지므로** 잔고는 맞지만, 표에서 "손익 +587, 수수료 646"처럼 셈이
안 맞아 보입니다. `js/trade-history.js`와 `js/realized-pnl-fix.js`가 표시를
보정합니다. 손익 계산을 건드릴 때 이 둘을 같이 보세요.

수수료율: 테이커 0.05% / 메이커 0.02% (바이낸스 실제와 동일).
100배에서 왕복 0.1%라 가격이 0.1% 움직여야 본전입니다.

## 5. 남은 일

### 오픈 전 반드시

1. **개인정보처리방침 페이지** — 없습니다. 네이버 검수에 필요하고 어차피 필요합니다
2. **네이버 검수요청** — 통과해야 일반 손님이 로그인할 수 있습니다(영업일 2~3일)
3. **TL이 계좌 초기화 때 사라지는 문제** — 확인 필요. 초기화 후 보유 TL이
   72,560 → 60으로 줄었습니다. 사용자는 "기존 TL을 초기화하지 말 것"을
   요구했습니다. `tl_earned()`가 거래 실적 기반이라 초기화와 함께 날아간 것으로
   보이는데, 아직 원인 확정 못 했습니다

### 미해결

4. **채팅창이 위아래로 흔들림** — 원인의 구조는 확인했습니다. 채팅 칸은 화면에
   고정(sticky)돼 있는데 그 위쪽 내용의 높이가 변하면 기준점이 밀립니다.
   `?jitter=1`을 붙이면 진단 도구가 켜져서 어느 부분이 몇 번 변했는지
   화면에 보여줍니다(`js/jitter-probe.js`). 측정 결과를 아직 못 받았습니다
5. **강제청산 알림 문구** — "강제청산되었습니다"만 있어 계좌 전체가 날아간 것처럼
   읽힙니다. "(증거금 -55,007,767원)"처럼 바꾸자고 제안했고 답은 못 받았습니다

### 의도적으로 안 고침

6. **강제청산 수수료** — 바이낸스는 명목가의 1.25~2%를 별도로 뗍니다. 우리는
   증거금 전액 손실까지만. 사용자가 "아직 건들지마"라고 했습니다
7. **펀딩비 미납분** — 잔고 0 근처에서 큰 포지션을 들면 거의 안 냅니다.
   증거금 차감은 청산 로직(수정 금지)을 건드려야 해서 보류

### 논의만 하고 미적용

8. **TL 경제 설계** — 지금 커피 한 잔(2,500 TL)에 190회 거래가 필요합니다.
   사용자 요구: "1천만원 단위 · 암산 불가 · 수익 커질수록 증가율 감소 ·
   많이 벌면 확실히 많이 받는 느낌 · TL을 게임 경제처럼".
   제안했던 식: `1500 × log₂(1 + 수익/1천만)`.
   **바꾸려면 화면(`js/rank.js`)과 서버(`tl_earned`) 양쪽을 함께 고쳐야 합니다**
9. **주문창 본전 가격 표시** — 100배는 왕복 수수료 0.1%라 그만큼 움직여야
   본전입니다. 주문 전에 보여주자고 제안했는데 "하지마"로 보류됐습니다
10. **기존 비밀번호 회원을 카카오·네이버에 연결** — 필요 여부 미결정

### Supabase에서 걸렸던 것들

- **WHERE 없는 DELETE·UPDATE는 거부됩니다**(safeupdate). 전체 삭제도
  `where id is not null` 같은 조건을 붙여야 통과합니다
- **오류를 감추지 마세요.** "실패했습니다"만 띄우니 원인을 못 찾았습니다.
  서버 메시지를 그대로 보여주게 바꾸자마자 원인이 한 번에 나왔습니다
- 트리거로 중복을 막을 때는 **오류를 내지 말고 `return null`로 조용히 무시**해야
  합니다. 오류를 내면 화면이 "저장 실패"로 보고 무한히 재시도합니다

## 7. 작업 환경 제약

- 이 환경에서 **Supabase·바이낸스가 차단**돼 있습니다. 시세도 채팅도 안 들어옵니다.
  로컬 검증 결과와 실제 사이트 동작이 다를 수 있습니다
- 그래서 **가짜 서버를 끼워 넣고 테스트**하는 패턴을 많이 씁니다.
  `page.addInitScript`로 `App.SupabaseClient.get`을 바꿔치기합니다
- Playwright는 `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` 를
  `executablePath`로 지정해야 뜹니다
- 테스트 파일은 **끝에서 `process.exit(0)`을 불러야** 합니다. jsdom 창이 타이머를
  붙들고 있어서 안 그러면 프로세스가 안 끝나고, `npm test`가 거기서 멈춰
  뒤 테스트가 아예 실행되지 않습니다
